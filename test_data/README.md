# Тестовые данные

Русская речь для проверки ASR, диаризации и обработки ошибок. Всё аудио
синтезировано через [edge-tts](https://github.com/rany2/edge-tts) голосами
`ru-RU-SvetlanaNeural` (Оператор) и `ru-RU-DmitryNeural` (Клиент) и
воспроизводится одной командой:

```bash
uv sync --group dev
uv run python scripts/make_test_data.py --force
```

Рядом с каждым позитивным аудиофайлом лежит эталонный транскрипт `.txt` в
формате `Спикер: реплика` — он же ground truth для диаризации, он же reference
для WER.

## Позитивные файлы

| Файл | Сценарий | Длит. | Формат | Что проверяет |
|---|---|---|---|---|
| `call_dialog.wav` | Консультация по кредиту наличными, Анна и Михаил (сценарий из [`docs/sample-dialog.md`](../docs/sample-dialog.md)) | 2:16 | WAV pcm_s16le, 16 кГц, моно | Основной кейс: диаризация двух говорящих, happy path всех четырёх агентов |
| `call_dialog_8k.wav` | Тот же звонок через телефонный кодек | 2:16 | WAV **μ-law, 8 кГц**, моно | Телефонное качество, апсемплинг до 16 кГц в `_format_audio` |
| `card_block.mp3` | Клиент срочно блокирует утерянную карту | 1:06 | **MP3, 44.1 кГц, стерео** | Формат MP3, downmix стерео→моно, ресемплинг вниз |
| `complaint_violation.wav` | Конфликтный звонок с нарушениями регламента | 1:01 | WAV pcm_s16le, 16 кГц, моно | Негативный сценарий **для агентов** (см. ниже) |
| `deposit_question.ogg` | Короткий вопрос по ставке вклада | 0:29 | **OGG/Opus, 48 кГц**, моно | Третий поддерживаемый формат |
| `short_greeting.mp3` | Односложное обращение, один говорящий | 0:05 | MP3, 22.05 кГц, моно | Граничный кейс очень короткого файла |

**Итого 7:12** — при требуемых пяти минутах. Покрыты все три формата из
`ALLOWED_EXTENSIONS`, пять разных sample rate (8/16/22.05/44.1/48 кГц) и оба
варианта каналов.

### `complaint_violation.wav` — что должны найти агенты

Сценарий написан так, чтобы дать агентам содержательный негатив:

- оператор **не здоровается и не представляется** → `quality_score.checklist.greeting = false`;
- **грубит и обесценивает проблему** («ничего страшного не произошло, само вернётся»);
- **обещает гарантированный результат** («вам сто процентов всё вернут, гарантирую») → нарушение для `compliance`;
- **обрывает разговор без прощания** → `checklist.farewell = false`;
- тема — жалоба на двойное списание → `classification.topic` про операции/жалобу, приоритет не `low`.

Остальные файлы — корректные звонки, на них чек-лист качества должен
проходить, а `compliance.passed` быть `true`.

## Негативные файлы (`negative/`)

Проверяют обработку ошибок в [`api/main.py`](../api/main.py). Прогоняются
автоматически в [`tests/test_audio_fixtures.py`](../tests/test_audio_fixtures.py).

| Файл | Что это | Ожидаемый ответ |
|---|---|---|
| `empty.wav` | Файл нулевой длины | `400 Uploaded file is empty` |
| `not_audio.txt` | Обычный текст | `400 Unsupported file type: .txt` |
| `corrupted.ogg` | Настоящий OGG с испорченными первыми 4 КБ (оборвавшаяся закачка) | `422 Failed to decode audio` |
| `no_audio_stream.wav` | Расширение разрешённое, но внутри MP4 только с видеодорожкой | `422 File contains no audio stream` |
| `silence_30s.wav` | 30 секунд тишины — **валидное** аудио без речи | `200`, пустой `transcript`, граф отрабатывает без обращения к LLM |

Два замечания по подбору негатива:

- **`corrupted.ogg` — не «WAV-заголовок плюс случайные байты».** Такой файл
  ffmpeg спокойно декодирует: случайные байты являются валидным PCM, на выходе
  получается шум, а не ошибка. Чтобы кейс действительно ловил ветку
  `Failed to decode audio`, портится начало настоящего сжатого потока.
- **Файл больше `MAX_UPLOAD_BYTES` в репозиторий не кладётся** — держать
  100 МБ в git ради одного кода ответа не стоит. Лимит проверяется на
  `call_dialog.wav` с временно уменьшенным `MAX_UPLOAD_BYTES`.

## Известные ограничения

- Речь **синтетическая**: дикция чище реальных звонков, нет перебиваний,
  фонового шума и наложения голосов. WER на реальных телефонных записях будет
  заметно выше. `call_dialog_8k.wav` частично компенсирует это, воспроизводя
  полосу телефонного канала.
- Роли в диаризации назначаются по индексу спикера
  (`SPEAKER_00 → Оператор`, [`asr/diarizer.py`](../asr/diarizer.py)), а не по
  содержанию реплик. Если в звонке первым говорит клиент — как в
  `short_greeting.mp3` — роли окажутся перепутаны.
